생성 이미지에 남은 선명한 블루·그라데이션·푸른 기본 보더는 그대로 복제하지 않고 합의한 단색 토큰과 마지막 사용자 지시를 적용했다.

### 이미지와 에셋

기준 화면은 텍스트, 색상칩, 표준 폼 컨트롤로 구성되어 별도 래스터 에셋이나 아이콘이 필요하지 않다. UI 전체를 이미지로 붙이지 않고 의미 있는 HTML과 CSS로 구현했다. 폰트는 프로젝트 내에 포함되어 외부 CDN에 의존하지 않는다.

### 문구와 내용

기준의 영어 제목·한글 설명·예시 값·상태 이름을 유지했다. 회색 토큰은 실제 값에 맞춰 `Border #C6C6CC`로 표기했다. 푸터는 `40px height / 0px radius / 8px spacing`이다.

## 비교 및 수정 이력

1. 초기 배치 점검에서 소개 영역과 하단 높이를 조정했다. 소개 영역 아래 여백을 8px 줄여 1484 × 1060 화면 안에 푸터까지 들어오도록 정리했다. 최종 증거는 `.qa/desktop.jpg` 및 전체 비교 이미지다.
2. [P2, 해결] 320px 모바일에서 body의 min-width 때문에 세로 스크롤바 너비만큼 가로 넘침이 발생했다. 수정 전 clientWidth 305px / scrollWidth 320px, 증거 `.qa/mobile-320-before.jpg`. body의 최소 너비 제한을 제거하고 작은 화면의 제목 최소 크기를 조정했다. 수정 후 둘 다 305px, 증거 `.qa/mobile-320.jpg`. 입력창·저장 버튼·토글이 잘리지 않는 것도 확인했다.
3. 수정 후 데스크톱을 같은 viewport·초기 상태로 재캡처했다. 기준과 구현을 전체 및 상태 영역 비교 이미지로 다시 확인했다. 남은 P0/P1/P2 발견 사항 없음.
4. 사용자가 기본 보더를 조금 더 또렷하게 요청했다. 컴포넌트 보더를 `#C6C6CC`로 바꾸고 헤더·소개·푸터 선은 별도 `--border-subtle: #DADADD`로 분리해 기존 색을 유지했다. 로컬 브라우저의 1484 × 1060 화면에서 최신 캡처 `.qa/border-update.png`를 확인했다. 실제 기본 보더는 rgb(198, 198, 204), 헤더 선은 rgb(218, 218, 221), 열 구분선은 rgb(226, 226, 229)로 검증했다. 포커스의 밝은 안쪽 2px 및 둥근 토글도 유지됨을 확인했다. 위 전체·부분 비교 이미지는 이 색상 조정 전의 레이아웃 검증 기록이며 최신 보더 색상 근거는 새 캡처다.
